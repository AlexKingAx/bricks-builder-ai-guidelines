## ⚠️ Nota su "non referenziata"

**Non è una lista di cose da cancellare.** La documentazione Bricks è esplicita: i dati sulle dipendenze *non dimostrano* che una risorsa sia inutilizzata o eliminabile in sicurezza.

L'audit non vede: CSS custom di pagine ed elementi, codice nel child theme, classi applicate via JavaScript, contenuti non ancora pubblicati.

In questo sito è atteso che molte risultino non referenziate: è uno **starter kit** portato da altri progetti, le classi vengono attivate man mano che servono.

## Stato reale dei riferimenti a variabili

Verificato scansionando le impostazioni di tutte le 64 classi:

| | Risultato |
|---|---|
| Classi che referenziano variabili inesistenti | **1** — solo `--vh` |
| Theme styles che le referenziano | **0** |

Le 10 variabili segnalate come orfane dall'audit (`--color-1…6`, `--color-8`, `--nero`, `--white`, `--vh`) **non vivono nelle classi globali né nei theme styles**: stanno nel CSS custom di pagine ed elementi.

**Conseguenza pratica:** le classi globali sono già pulite rispetto alla palette. Il raccordo alla palette nuova va fatto nel CSS delle pagine, non qui.

`--vh` è corretta così: viene impostata da JavaScript a runtime e ha il fallback `1vh`. Non toccarla.
